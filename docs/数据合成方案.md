# 数据合成方案

## 一、设计初衷

金融大模型（Financial LLM）的训练面临一个核心瓶颈：**高质量、多难度层次的训练数据极度稀缺**。传统数据合成方法往往生成的数据过于简单、单一，无法满足 Process Reward Model (PRM) 和 SFT 训练对数据多样性、难度分层、正负样本配比的要求。

本系统的设计目标：

1. **多难度覆盖**：从简单的单一指标计算到复杂的综合风险评估，覆盖 0.1~1.0 全难度谱系
2. **多源样本对比**：同一问题下同时产出标准答案、正样本、刻意负样本、策略模型自然样本，形成对比训练数据
3. **真实错误暴露**：利用小模型（qwen3-8b）的自然推理弱点，获取最真实的负样本，而非人工构造的刻板错误
4. **质量闭环**：每个样本经过独立验证，确保正样本的正确性和负样本的"迷惑性"

## 二、双模型分工架构

系统采用**双模型 Multi-Agent 架构**，将"智能生成"和"自然采样"彻底分离：

```
┌─────────────────────────────────────────────────────────────────┐
│                     qwen3.7-max (235B)                          │
│                    主力模型 · 智能生成                           │
│                                                                 │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐       │
│  │  提议者   │  │ 正样本    │  │ 负样本    │  │  验证者   │       │
│  │ Proposer │  │ 求解者    │  │ 求解者    │  │ Validator│       │
│  │          │  │          │  │          │  │          │       │
│  │ 出题 +   │  │ 正确     │  │ 刻意     │  │ 正样本   │       │
│  │ 标准答案 │  │ 分步推理  │  │ 注入错误  │  │ 验证     │       │
│  └──────────┘  └──────────┘  └──────────┘  │ 负样本   │       │
│                                              │ 质量评估 │       │
│  Temp: 0.8     Temp: 0.2     Temp: 0.7     │ 策略样本 │       │
│                                              │ 标注     │       │
│                                              │          │       │
│                                              │ Temp:0.05│       │
│                                              └──────────┘       │
└─────────────────────────────────────────────────────────────────┘
                              │
                              │ 问题
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                     qwen3-8b (8B)                               │
│                    策略模型 · 自然推理                           │
│                                                                 │
│  ┌──────────────────────────────────────────────────────┐      │
│  │              策略模型采样器                            │      │
│  │              StrategyModelSampler                     │      │
│  │                                                       │      │
│  │  纯推理 Prompt（无错误注入引导）                        │      │
│  │  "请分析以下财务问题：{question}"                      │      │
│  │                                                       │      │
│  │  Temp: 0.7 · 每个问题采样 N 次（默认3次）              │      │
│  └──────────────────────────────────────────────────────┘      │
│                                                                 │
│  做对 → 正样本（暴露模型真实能力边界）                            │
│  做错 → 负样本（暴露模型真实推理弱点）                            │
└─────────────────────────────────────────────────────────────────┘
```

### 为什么这样分工？

| 设计决策 | 原因 |
|----------|------|
| 235B 负责所有"智能"工作 | 出题、解题、验证都需要强推理能力，大模型才能保证质量 |
| 8B 只做最朴素的推理 | 去除所有引导，让其以最自然状态推理，暴露真实的强弱项 |
| 8B 输出由 235B 标注 | 标注本身是复杂判断任务，需要大模型的判别能力 |
| 两个模型独立推理 | 8B 的样本不受 235B 推理路径影响，保持独立性 |

## 三、工作流（LangGraph Pipeline）

### 3.1 整体流程

```
                        ┌─────────────┐
                        │  JSON 上传   │  财务数据 + 评估维度
                        └──────┬──────┘
                               │
                        ┌──────▼──────┐
                        │  任务调度    │  TaskManager → ThreadPoolExecutor
                        └──────┬──────┘
                               │
                    ┌──────────▼──────────┐
                    │  对每个任务（公司）   │
                    │  生成 N 个问题       │
                    │  (MAX_ITERATIONS=5) │
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              │  每个问题独立，随机难度 0.1~1.0  │
              └────────────────┼────────────────┘
                               │
        ┌──────────────────────┼──────────────────────┐
        │                      │                      │
        ▼                      ▼                      ▼
   问题 1                   问题 2                 问题 N
        │
        │ （每个问题的处理流程如下）
        ▼
```

### 3.3 每个问题的数据产出

```
同一个问题
    │
    ├──→ 235B 提议者 ──→ 【标准答案 + 标准分析过程】──────────────┐
    │     (proposer_system_prompt)                                 │
    │                                                              │
    ├──→ 235B 正样本求解者 ──→ 【正样本】──→ 正样本验证者 ──→ 通过/不通过
    │     (solver_system_prompt)              (对比标准答案)
    │     Temp 0.2
    │
    ├──→ 235B 负样本求解者 ──→ 【负样本】──→ 负样本验证者 ──→ 有效/无效
    │     (negative_solver_prompt)             (检查实质性差异)
    │     注入7类专业错误                       要求: 有迷惑性
    │     Temp 0.7
    │
    └──→ 8B 策略模型 (×3) ──→ 【待标注样本】──→ 策略样本验证者 ──→ 标注正/负
          (sampling_prompt)                      (对比标准答案)
          纯推理，无引导                          暴露8B真实能力
          Temp 0.7
```

## 四、训练数据构成

### 4.1 每问题的产出

| 产出 | 来源模型 | 样本类型 | 用途 |
|------|---------|----------|------|
| 标准答案 | qwen3.7-max 提议者 | 参考答案 | 验证基准 |
| 正样本 (×1) | qwen3.7-max 求解者 | 正确推理 | PRM 正例 |
| 负样本 (×1) | qwen3.7-max 求解者 | 含迷惑性错误 | PRM 负例 |
| 策略样本 (×3) | qwen3-8b 策略模型 | 自然的对/错 | PRM 核心训练数据 |

### 4.2 总体占比目标

| 数据来源 | 扮演者 | 样本类型 | 占比 | 价值定位 |
|----------|--------|----------|------|----------|
| qwen3.7-max 正样本 | 求解者 | 正确推理 | ~20% | 教科书级范例 |
| qwen3.7-max 负样本 | 负样本求解者 | 含迷惑性错误 | ~20% | 高质量反例 |
| **qwen3-8b 自然采样** | 策略模型 | 自然正确/错误 | **~60%** | **最真实的训练数据** |

### 4.3 为什么 8B 策略模型占 60%？

1. **真实性**：8B 模型的错误是真实的推理弱点，不是人工构造的，对 PRM 训练价值最高
2. **多样性**：每次采样的推理路径不同，可能正确也可能错误，提供丰富的对比信号
3. **暴露弱点**：直接反映小模型在财务推理上的具体短板（计算、逻辑、理解等）
4. **迁移价值**：用 8B 的错误模式训练的 PRM，泛化到其他小模型效果更好

## 五、负样本错误注入体系（7 类）

qwen3.7-max 负样本求解者通过 Prompt 引导，在推理中**自然地**注入以下错误类型：

| # | 错误类型 | 描述 | 示例 |
|---|---------|------|------|
| 1 | 计算错误 | 财务比率计算故意算错 | 毛利率分子/分母颠倒 |
| 2 | 公式引用错误 | 使用错误的计算公式 | 用 ROA 替代 ROE |
| 3 | 指标理解错误 | 混淆相似指标含义 | 将经营现金流理解为净利润 |
| 4 | 逻辑跳跃 | 缺失关键中间步骤 | 直接从数据跳到结论 |
| 5 | 因果倒置 | 颠倒财务指标因果关系 | "盈利下降导致毛利率下降" |
| 6 | 数据误读 | 引用错误的数据值 | 用其他公司数据代入 |
| 7 | 趋势误判 | 对数据变化趋势判断错误 | 数据显示上升却说下降 |

**关键约束**：错误必须自然、有迷惑性，不能过于明显。输出应该像"一份有缺陷的专业分析报告"而非"一份明显错误的答案"。

## 六、验证闭环

### 6.1 三种验证逻辑

| 验证类型 | 验证对象 | 验证逻辑 | is_valid 含义 |
|----------|---------|----------|---------------|
| 正样本验证 | qwen3.7-max 正样本 vs 标准答案 | 核心结论一致、推理正确 | true = 正样本正确 |
| 负样本验证 | qwen3.7-max 负样本 vs 标准答案 | 存在实质性差异但有迷惑性 | true = 负样本有效（错误质量好） |
| 策略样本验证 | qwen3-8b 输出 vs 标准答案 | 判断对错，标注正/负 | true = 8B 做对了（正样本） |

### 6.2 验证标准

- **核心结论一致性**：最终结论语义上是否一致
- **推理逻辑正确性**：分析步骤是否符合财务逻辑
- **数据使用准确性**：财务数据是否正确使用
- **完整性**：是否涵盖问题关键方面

验证温度设为 **0.05**（近乎确定性），确保评判标准稳定一致。

## 七、技术架构

### 7.1 技术栈

| 组件 | 技术 |
|------|------|
| 工作流引擎 | LangGraph (StateGraph) |
| LLM API | OpenAI-compatible (阿里 DashScope) |
| 主力模型 | qwen3.7-max (235B) |
| 策略模型 | qwen3-8b (8B) |
| 数据模型 | Pydantic v2 |
| Web UI | Gradio |
| 持久化 | SQLite |
| 并行处理 | ThreadPoolExecutor |

### 7.2 目录结构

```
project_root/
  config/
    settings.py       # 系统参数（迭代数、难度范围、阈值等）
    llm_config.py     # 双模型配置（API key、温度、tokens）
    prompts.py        # 12 个 Prompt（7 对 system/user）
  src/
    models.py         # Pydantic 数据模型
    agents.py         # LLM 客户端 + 4 个 Agent 类
    graph.py          # LangGraph 工作流
    database.py       # SQLite 持久层
    task_manager.py   # 任务生命周期管理
    parallel_processor.py  # 并行处理
  web_ui/
    app.py            # Gradio 主应用
    components.py     # UI 组件构建
    handlers.py       # 事件处理器
  services/
    html_generator.py # 结果 HTML 渲染
  data/
    outputs/          # 生成结果 JSON + synthesis.db
```

### 7.3 核心配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| MAX_ITERATIONS | 5 | 每任务生成问题数 |
| MIN_DIFFICULTY | 0.1 | 最低随机难度 |
| MAX_DIFFICULTY | 1.0 | 最高随机难度 |
| STRATEGY_SAMPLE_COUNT | 3 | 每问题 8B 采样次数 |
| PARALLEL_TASK_COUNT | 3 | 并行任务数 |
| VALIDATION_THRESHOLD | 0.8 | 正样本验证通过阈值 |
